# 01: 建立可运行的 flow-core 工作区

**What to build:** 让项目负责人可以在隔离项目中运行 `flow-core`，诊断运行环境并初始化一个可供后续流程使用的项目工作区。初始化需要建立项目规则基线、团队配置、项目约束模板和 P0 所需的目录骨架，同时保留已有业务内容。该切片也建立后续命令共用的结构化结果、原子单文件写入和对象锁基础。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] CLI 提供人类可读输出和 `--json` 输出；成功结果包含 `success`、`artifacts`、`errors`、`next_actions`，失败返回非零退出码。
- [x] `init` 在空项目中创建完整 P0 骨架、项目规则基线、团队配置模板和项目约束模板，不伪造业务内容。
- [x] 初始化可显式裁剪允许裁剪的非核心内容，但核心需求、PRD 门禁和人工验收能力始终保留。
- [x] 已有 README、AGENTS、业务文档和代码不会被静默覆盖；冲突会先返回变更计划；重复初始化保持幂等。
- [x] `doctor` 能检查 Python、Node.js、Skill 资源、`flow-core` 可用性和残留锁，并返回可操作的修复建议。
- [x] 单文件更新使用原子替换；同一需求或 PRD 的并发写入被对象锁拒绝；失败不改变正式内容或业务状态。
- [x] CLI 黑盒测试覆盖空项目、重复初始化、已有文件、失败退出码、JSON 结果和并发冲突。
