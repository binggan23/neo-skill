# 02: 完成需求对齐与人工排期

**What to build:** 让需求提出者可以创建并恢复 `NEW` 需求，使用 grilling 逐轮收敛背景、用户、问题、场景、期望结果和来源，并看到重复或关联提示。需求负责人完成共识确认后，系统必须明确询问是否设置需求排期；只有职责匹配的需求负责人明确同意并确认目标版本，需求才进入 `PLANNED`。

**Blocked by:** 01: 建立可运行的 flow-core 工作区

**Status:** resolved

- [x] 可创建、保存和恢复 `NEW` 需求，需求具备稳定 ID、slug、模块、分类、来源和必要内容。
- [x] grilling 使用设计树和 frontier 逐轮提问，区分可查证事实与人工决策，并在推进前展示共识摘要、假设和未决问题。
- [x] 系统能提示已有需求或功能现状的重复/关联关系，未获人工确认时不删除或合并原需求。
- [x] 需求支持新功能、优化、缺陷和技术债分类，并记录优先级及理由。
- [x] 共识未确认时保持 `NEW`；确认后才进入 `TRIAGED`。
- [x] 明确询问“是否设置 xxx 需求排期”；拒绝排期或缺少目标版本时不进入 `PLANNED`。
- [x] 需求负责人身份和职责匹配后，明确同意排期并确认版本才进入 `PLANNED`，同时记录人工决定和状态历史。
- [x] CLI 黑盒测试覆盖草稿恢复、重复提示、未确认、拒绝排期、缺版本、职责不匹配、合法排期和非法状态跳转。
