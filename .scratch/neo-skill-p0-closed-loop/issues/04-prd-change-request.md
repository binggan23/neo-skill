# 04: 通过 CR 安全变更已批准 PRD

**What to build:** 让团队可以在不破坏已批准基线的情况下修改 PRD。直接编辑造成的基线变化必须被发现并阻止继续开发；合法变更通过 CR 记录原因、影响和审批信息，使旧 Spec、代码和验证证据失效；重新批准后形成新的 PRD 版本和 hash，同时保留旧历史。

**Blocked by:** 03: 完成 PRD 草稿、评审与批准基线

**Status:** ready-for-agent

- [ ] 已批准 PRD 的锁定内容不能通过普通流程直接修改或继续使用；hash 变化会使门禁失败并报告基线失效。
- [ ] 可以创建属于指定 PRD 的 CR，并记录变更内容、原因、对 Spec/Tasks/测试/设计/版本的影响、版本变化和审批信息。
- [ ] 开发或验收相关基线发生 CR 后，已有 Spec、代码、测试和验收证据保留但明确标记为失效。
- [ ] CR 会使 PRD 返回评审流程，未重新批准前不能继续正式开发或沿用旧验收结论。
- [ ] 重新批准会递增 PRD 版本并生成新 hash；旧批准、旧验收和历史记录仍可查询。
- [ ] 评审记录、CR 和状态历史追加不会被误计入正文 hash。
- [ ] CLI 黑盒测试覆盖直接篡改检测、创建 CR、基线失效、重新评审、重新批准和旧历史保留。
