# 06: 生成验证证据并提交人工验收

**What to build:** 让开发者可以执行适用的单元测试、集成测试和静态检查，并生成与每条 AC 关联的验证证据。系统保留原始输出、退出码、执行环境和代码版本；只有所有适用验证项通过后，PRD 才能进入 `READY_FOR_ACCEPTANCE`，并提醒人工验收。

**Blocked by:** 05: 从有效 PRD 启动开发

**Status:** resolved

- [x] 可以执行项目声明的适用验证命令，并保存每条 AC 的验证结果、原始输出、退出码和执行环境。
- [x] 提交验收时记录 Git commit；非 Git 项目记录纳入范围的源代码和测试内容摘要。
- [x] 未执行、失败或阻塞的验证不能被标记为通过；不适用项必须有明确理由。
- [x] 测试失败时允许受限自动修复，默认最多连续三轮；不能删除用例、降低断言、跳过测试或修改 AC 制造通过。
- [x] 所有适用验证项通过且验证报告完整后，PRD 才能进入 `READY_FOR_ACCEPTANCE`。
- [x] PRD、代码或验证证据变化会使提交验收基线失效，并返回重新验证的下一步。
- [x] CLI 黑盒测试覆盖成功验证、失败验证、修复上限、缺失证据、伪造通过、代码版本记录和基线变化。
