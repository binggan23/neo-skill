# 07: 完成需求负责人的人工验收

**What to build:** 让验收人员获得 Demo 材料和按 AC 生成的 checklist，并逐项记录通过、不通过或阻塞及证据。AI 可以提出建议，但只有全部 AC 通过且需求负责人完成身份/职责核对并明确确认，PRD 才能进入 `ACCEPTED`；有条件通过、不通过或阻塞必须保留问题并阻止错误完成。

**Blocked by:** 06: 生成验证证据并提交人工验收

**Status:** ready-for-agent

- [ ] 能根据 PRD 和验证证据生成 Demo 材料与逐条 AC checklist。
- [ ] 每条 AC 必须记录通过、不通过或阻塞，以及对应的人工或技术证据。
- [ ] AI 可以建议结论，但不能直接写入人工验收通过结论或 `ACCEPTED` 状态。
- [ ] 只有全部 AC 为通过时才允许请求“验收通过”确认；有条件通过、阻塞或不通过时不能进入 `ACCEPTED`。
- [ ] 只有职责匹配的需求负责人带显式确认才能将 PRD 从 `READY_FOR_ACCEPTANCE` 转为 `ACCEPTED`。
- [ ] 验收报告记录验收人、时间、PRD hash、代码版本或内容摘要、逐项结论和遗留问题。
- [ ] 不通过的验收退回 `DEVELOPING`；有条件通过保留问题并提供退回或重新验收的下一步。
- [ ] CLI 黑盒测试覆盖建议与人工确认分离、错误身份、全部通过、不通过、阻塞、有条件通过和验收版本变化。
