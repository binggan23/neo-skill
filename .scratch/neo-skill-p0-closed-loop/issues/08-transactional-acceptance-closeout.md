# 08: 完成可恢复的验收收尾

**What to build:** 让已经人工确认通过的 PRD 完成一致性收尾。系统以可恢复事务同步功能现状、主需求、场景状态和索引；全部同步成功后主需求才进入 `DONE`。如果进程中断或部分写入失败，系统保留“已确认通过，收尾未完成”，并允许在基线未冲突时恢复，不得静默覆盖新修改。

**Blocked by:** 07: 完成需求负责人的人工验收

**Status:** ready-for-agent

- [ ] 验收确认后的收尾事务包含功能现状、主需求、场景状态和受管理索引的同步目标。
- [ ] 事务有 `PREPARED`、`COMMITTING` 和 `COMMITTED` 三个可恢复阶段，并保留目标、原基线、暂存内容和操作顺序。
- [ ] 所有同步成功后 PRD 保持 `ACCEPTED`，主需求才进入 `DONE`，场景状态与索引保持一致。
- [ ] 任一步失败时保留人工验收结论和错误，并明确显示“已确认通过，收尾未完成”；不能报告全部完成。
- [ ] `recover` 会重新获取对象锁并验证原基线；基线冲突时拒绝静默覆盖并返回恢复建议。
- [ ] 首次验收的新功能会创建功能现状；已有功能现状会记录本次变化。
- [ ] 索引只更新受管理区块并保留区块外人工内容；索引失败不回滚或改变已经确认的业务结论。
- [ ] CLI 黑盒测试覆盖完整收尾、中断恢复、部分失败、基线冲突、首次功能现状和主需求未完成状态。
