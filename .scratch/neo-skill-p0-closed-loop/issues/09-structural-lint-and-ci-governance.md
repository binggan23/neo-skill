# 09: 建立结构检查与 CI 治理

**What to build:** 让项目负责人和 CI 可以对完整 P0 工作区执行一致性检查，发现缺失产物、ID 或引用错误、孤儿 Spec、失效基线、验收收尾不完整以及绕过 Skill 的直接编辑。检查结果必须可机器消费、以非零退出码阻止违规结果，并在目标数据规模下满足性能要求。

**Blocked by:** 08: 完成可恢复的验收收尾

**Status:** ready-for-agent

- [ ] `lint` 检查必需目录和产物、ID 与目录/metadata 一致性、孤儿 Spec、失效引用和非法状态关系。
- [ ] `lint` 能发现 PRD hash、代码版本、验证证据或验收基线失效，并给出对象、错误码和恢复建议。
- [ ] `lint` 能发现验收后功能现状、主需求、场景或索引未完成同步。
- [ ] 结构检查和索引生成支持人类输出与 JSON 输出，失败返回非零退出码且不修改业务状态。
- [ ] 相同输入和规则生成稳定的检查/索引结果；受管理区块外内容不会被覆盖。
- [ ] CI 可以直接运行检查和自动化测试，并根据非零退出码阻止违规结果。
- [ ] 在约 1,000 条需求或 200 个 PRD 的 fixture 上，常规 lint、索引和状态查询在 10 秒内完成，单次状态变更在 2 秒内完成（不含 AI 和项目测试）。
- [ ] 日志、错误和 CI 输出不包含凭据；直接编辑的限制以流程治理能力而非不可绕过安全边界呈现。
- [ ] CLI 黑盒测试覆盖每类结构违规、稳定输出、CI 失败传播、目标数据规模和敏感信息检查。
